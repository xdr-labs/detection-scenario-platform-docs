# 시나리오 범위

DSP는 `scenarios/<id>/` 아래의 Scenario Plugin을 사용합니다. 현재 Operational Profile 순서에는 고객 POC에서 사용할 수 있는 11개의 주요 Scenario가 포함되어 있습니다. Runtime은 추가 Internal/Test Plugin을 발견할 수 있으므로 특정 설치 환경에서의 최종 기준은 `dsp plugins list`입니다.

## Operational Scenario Set

| Scenario ID | Category | 생성하는 Activity | 일반적인 POC Signal |
| --- | --- | --- | --- |
| `host_behavior_check` | Endpoint / EDR | Endpoint Telemetry를 위한 통제된 Host-side File/Process Behavior | EDR / Host Behavior |
| `port_sweep` | Network | 선택된 Host/Port에 대한 TCP Probe | Scan / Reconnaissance |
| `http_followup` | HTTP / Web | 발견된 HTTP Service에 반복 Request 및 Attack-oriented Path 전송 | Web Scanning / Suspicious Request |
| `sql_injection` | HTTP / Web | Time-based 및 `UNION SELECT` Pattern을 포함한 SQL Injection 형태의 Request | WAF / NDR Web Attack |
| `ssh_failure` | Identity / SSH | 반복적인 SSH Authentication Failure | SSH Brute-force / Auth Failure |
| `ldap_enumeration` | Identity / LDAP | LDAP 접근이 가능한 경우 Bind/Query Enumeration 형태 Activity | Directory Enumeration |
| `smb_login_failure` | Identity / SMB | 반복적인 SMB Authentication Failure | SMB Bad-auth / Brute-force Signal |
| `kerberos_failure` | Identity / Kerberos | 발견된 Service에 Kerberos Failure Attempt | Identity / Pre-auth Failure |
| `dga` | DNS | Algorithmically Generated Domain Activity | DGA / DNS Anomaly |
| `rare_protocol_activity` | Network Behavior | 설정된 Burst Behavior를 포함한 낮은 빈도 또는 비정상 Protocol Activity | Rare Protocol / Anomaly |
| `dns_tunnel` | DNS / Exfil-style | 구조화된 DNS Query Payload Activity | DNS Tunneling / Exfil-style Detection |

<Note>
이 표는 **DSP가 생성하는 Activity와 해당 Activity가 자극하도록 설계된 Signal 유형**을 설명합니다. 특정 Vendor가 반드시 Alert을 생성한다는 의미는 아닙니다.
</Note>

## 고객 POC 관점의 Scenario 분류

POC에서는 Scenario를 다음과 같이 더 단순한 Story로 설명할 수 있습니다.

### HTTP / Web

- URL Scanning 및 HTTP Follow-up
- Attack-oriented Web Path
- SQL Injection Attempt
- 필요한 경우 Non-standard Port HTTP Burst Activity

### SSH

- 발견된 SSH Service에 반복 Login Failure

### SMB / LDAP / Kerberos

- 해당 Service가 존재할 때 Authentication Failure 및 Enumeration 형태 Activity

### Network Behavior

- Port Sweep
- Rare Protocol Activity
- DNS Tunnel
- DGA 형태 DNS Behavior

### Endpoint / EDR

- `host_behavior_check`는 Endpoint Telemetry 및 Evidence 확인을 위한 통제된 Host Activity를 생성합니다.

### Webshell 기반 내부 확장

검증된 JSP/PHP Webshell Provider를 사용하면 동일한 Scenario Framework가 Remote Host에서 Internal Scan, Discovery, Service-specific Traffic, DNS Activity 및 Host Behavior를 발생시킬 수 있습니다.

## Profile 동작

현재 두 Profile은 동일한 순서의 Scenario Set을 실행합니다.

```text
host_behavior_check → port_sweep → http_followup → sql_injection
→ ssh_failure → ldap_enumeration → smb_login_failure
→ kerberos_failure → dga → rare_protocol_activity → dns_tunnel
```

차이는 Target Coverage입니다.

- `normal` — 제한된 대표 대상, Service-oriented Scenario는 일반적으로 최대 2개 대상
- `high` — 대상별 Volume은 동일하며 Guardrail 범위에서 발견된 모든 대상으로 확장

DNS Tunnel은 현재 Traffic Profile에서 별도의 Host Selection Contract를 사용하며 DGA Resolver Behavior도 Scenario별로 처리됩니다.

## 특정 Scenario만 실행하는 예시

Advanced Operator는 전체 Profile 대신 일부 Scenario만 실행할 수 있습니다.

```bash
dsp run \
  --scenarios port_sweep,http_followup,dns_tunnel \
  --profile normal \
  --target-net 10.10.10.0/24
```

## Plugin Discovery

설치된 버전에서 Active Registry를 확인하려면 다음을 실행합니다.

```bash
dsp plugins list
```

Development Branch에 추가 Scenario가 있거나 Validation/Load 상태 때문에 Plugin이 Disabled된 경우 이를 확인하는 데 유용합니다.
