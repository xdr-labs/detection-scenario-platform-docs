# Detection Scenario Platform (DSP)

**XDR 및 NDR 고객 POC 검증을 위한 현실적이고 관찰 가능한 보안 활동을 생성합니다.**

DSP는 고객 환경이 너무 조용해 평가 기간 동안 충분한 탐지 사례를 보여주기 어려울 때 사용하는 POC 도구입니다. 접근 가능한 대상을 확인하고 통제된 시나리오를 실행한 뒤, 실제로 무엇을 생성했는지 기록해 XDR/NDR 탐지 결과와 비교할 수 있도록 남깁니다.

<Note>
DSP가 확인해 주는 것은 **어떤 활동을 생성했는가**입니다. 특정 Alert이 발생했거나 XDR Case가 성공적으로 연결되었다고 자동 판단하지 않습니다. 탐지와 Case 결과는 연결된 보안 플랫폼에서 별도로 확인해야 합니다.
</Note>

## 가장 빠르게 사용하는 방법

<Steps>
  <Step title="DSP 설치">
    Python 3.11+, Git, curl이 설치된 Linux 호스트에서 다음을 실행합니다.

    ```bash
    curl -fsSL https://raw.githubusercontent.com/xdr-labs/xdr-poc-script/release/v1.4.0-rc/install-dsp.sh | bash
    ```
  </Step>
  <Step title="첫 실행 설정">
    Menu에서 **Configure environment**를 선택하고 승인된 대상 CIDR을 입력한 뒤, Execution Mode는 **local**, Profile은 **normal**을 선택합니다.
  </Step>
  <Step title="실행 및 결과 확인">
    **Run scenario**를 실행한 뒤 **Show latest report**에서 DSP가 생성한 결과를 확인합니다.
  </Step>
</Steps>

## 준비할 것

가장 단순한 첫 실행에는 다음이 필요합니다.

- **Python 3.11+**, `git`, `curl`이 설치된 Linux 운영 호스트
- 테스트가 허가된 **Target CIDR**
- DSP Host에서 대상 네트워크로의 연결
- Detection 결과를 확인할 XDR/NDR 콘솔 접근 권한

일반적인 DSP 실행에는 **XDR API Token이 필요하지 않습니다**. Webshell 모드는 활동을 고객 네트워크 내부의 승인된 호스트에서 발생시켜야 할 때만 사용합니다.

## 현재 검증 범위

DSP v1.4.0은 **READY WITH KNOWN LIMITATIONS** 상태입니다. local 실행과 실제 JSP/PHP Webshell 실행은 검증되었습니다. ASPX/Windows IIS는 실제 Windows 런타임 검증이 끝나지 않아 Preview로 제공합니다.
